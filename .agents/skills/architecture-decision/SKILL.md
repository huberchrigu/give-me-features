---
name: architecture-decision
description: Record a consequential architectural decision when a repository specification leaves a cross-cutting technical choice open.
---

Create a concise ADR in `docs/adr` only for lasting choices affecting module
boundaries, data ownership/identity, lifecycle semantics, integrations,
security, or operations. Do not create ADRs for routine implementation detail.

Include status, context, decision, alternatives, consequences, and related
specifications. Describe an actual decision; if unresolved, write a Draft
proposal. Update linked specifications and architecture documentation when it
changes stated behavior. Mark replaced ADRs Superseded rather than rewriting
history.
